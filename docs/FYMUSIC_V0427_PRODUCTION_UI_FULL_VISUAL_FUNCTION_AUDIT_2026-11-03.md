## 确认问题与建议

### P2：移动导航标题仍是「LX Music」

**实际截图确认**：移动端打开汉堡菜单后，左侧抽屉顶部写着 **LX Music**，但主站顶部与页面标题均叫 FyMusic。位置：`src/mobile-shell.js` 中 `drawerName.textContent='LX Music'`。可安全改为 `FyMusic`，安排到待发布 PR #108 的视觉清理中并复测手机菜单。此项是当前最明确、可复现的正式界面不一致。

### P2：评论接口偶发 502，刷新可恢复

真实 `/api/netease-comments` 曾在一次播放详情会话返回 502。前端显示「平台暂未返回热门评论，可以刷新或前往原平台查看」，未造成 JS 崩溃。之后在独立测试中的两次请求均返回 200 和 15 条评论；建议记录上游请求失败比例、分离无评论/接口错误提示与 retry/backoff。它是上游可用性改善事项，不构成整个评论功能缺失。

### P2/P3：受第三方支持范围限制的音质体验

野花的当前网易云频道仅报告 128k，自动播放最终请求 128k。强制 320k+关闭降级时，正式站明确显示「当前野花渠道未声明支持 320k。可用：128k。未擅自改成128k」，正确阻止隐性降级。**无法证实网站存在 128k 的统一编码上限**；建议在设置渠道选择时提前展示每个渠道声明的可用规格，减少用户误以为选项 320k 就一定能播放的困惑。实际音频编码码率未通过文件解析验证。

### P3：技术型状态文案影响现代 UI 一致性

实际顶部状态常出现「音源已打开并发送 inited：野花」，属于内部 LX Runtime 术语；对非技术用户可替换为「野花音源已就绪」。设置页仍带「LX 音源管理」是兼容协议名称，**不应简单视为旧品牌**，但移动抽屉作为产品品牌确实应更名。空状态及数据加载状态已有基本反馈，可进一步增加骨架屏与离线模式清晰提醒；这些是 UX 优化建议而非本次证明的故障。

### 体验取舍，不是本轮故障

手机底部迷你播放器为了宽度只突出播放和下一首，全屏歌词页面仍提供上一首、下一首、进度 Seek、音量控制与模式切换。若用户期望手机底部直接 Seek，可在后续迭代另做需求评估；不能称为“功能不存在”。页面短暂网络加载出现「正在加载歌单」「正在读取榜单歌曲」，真实接口后续完成。

## 尚需真实设备确认

本审计的 WebKit 来自 Linux 无头 Playwright，不能代表真实 iOS Safari 帧率、后台播放/锁屏媒体控制。也未验证所有五个平台、所有地区和所有歌曲都能播放。之前记录的 WebKit 偶发长帧仍在 #106；用户此前报告过手动验收通过，但无完整设备跟踪数据。
