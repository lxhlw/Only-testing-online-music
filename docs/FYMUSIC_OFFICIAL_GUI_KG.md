# FyMusic — 完整官方 LX Music GUI 的 KG 搜索与播放证据

## 本轮云端测试

- GitHub Actions: https://github.com/lxhlw/Only-testing-online-music/actions/runs/41100174880
- 官方安装包：LX Music Desktop v2.12.6 Windows x64 green 便携版，未修改可执行文件。
- 同一公开野花脚本：`https://raw.githubusercontent.com/pdone/lx-music-source/main/flower/latest.js`。
- 通过官方 GUI 导入及选中野花，质量首选设置为 `flac24bit`；**实际向野花提交的音质尚未捕获**。
- 目标：孙燕姿《开始懂了》。所有操作经 GUI 触发，不以自造歌曲元数据取代官方搜索结果。
- 本轮修复旧 GUI 测试的时序：在**点击平台频道标签之后重新按 Enter 发起搜索**，没有只切换到旧查询结果。

KG 搜索界面明确显示了“开始懂了 / 孙燕姿 / 我要的幸福”；
另外还有同名的“黑胶版”、“Live”等不同版本。
官方 GUI 选择并点击了精确歌名和歌手的第一条，而不是播放其他歌曲。

播放器相关 CDP Media 事件：KG 15、WY 17、TX 17；
测试未发现可直接观察的 HTML `audio` / `video` 元素。
**仅凭播放器 UI 时间推进、CDP 事件计数和歌曲标签，不能宣称已独立证明音频媒体解码成功、确切播放音质或音频内容身份。**

## 与此前结果对照

- 上一次官方 GUI 测试在默认平台搜索后只切换标签，KG 行数为 0。本轮显式重新搜索后 KG 得到目标歌曲，说明之前的“KG 未找到”**不能作为平台无该歌的证据**。
- 之前在 Windows 使用官方 LX v2.12.6 原始 preload / IPC 且复用 FyMusic Web 搜索的两条 KG musicInfo，都没有取得 URL。本轮完整 GUI 所用的是**官方 KG 原生搜索结果**，并没有证明与那两条候选的 song ID/hash 相同。
- 之前 FyMusic Web 的野花 KG 解析代理返回聚合 502；原始 TCP 线路曾给出 400。完整 GUI 此次没有直接采集 Native Needle HTTP 请求或上游返回码，因此不能简单用 GUI 进度认定预加载组件成功解析，也不能将两个环境的响应作相同请求结论。
- 这些差异提示下一阶段优先比较官方 GUI 与 Web 的**选中候选元数据、身份映射及实际 musicUrl 请求**。应只导出相等性布尔值/安全分类，不暴露 ID、Hash、签名或私密 URL。

## 下一阶段（不在本轮擅自修改）

1. 借助 CDP 只读界面状态和官方仓库代码定位 GUI 实际采用的候选身份及质量选择规则；
2. 对同一个 KG 目录版本生成脱敏一致性检查，不仅对比歌曲名歌手；
3. 只有在能确认所用候选与质量相同以后，比较 original GUI Native Needle 和 FyMusic 网络传输差异。
4. 维持正式 main 不变，不强制低音质、不绕开第三方平台权限。
