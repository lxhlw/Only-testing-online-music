# FyMusic — 第一阶段：可信播放验证

## 本阶段范围

本阶段不改正式 \`main\`、不迁移 Cloudflare、不接入自动换源、不宣称第三方商业歌曲可用。

诊断模块仅旁路监听现有音频播放器：

1. \`lx:trackchange\` — 选中歌曲（不是已找到 URL）。
2. \`fymusic:url-resolved\` — 当前解析器已提供 URL（不是可播放证明；**不记录 URL 或签名**）。
3. 原生 \`loadedmetadata\` / \`canplay\` — 浏览器获得媒体元信息及解码准备证据。
4. 原生 \`playing\` — 播放开始事件（仍不足以单独证明进度）。
5. 原生 \`timeupdate\` — 至少两次合理时间推进，排除手动 seek、暂停、异常跳变。
6. \`error\` / \`stalled\` / \`waiting\` / \`ended\` — 记录失败、缓冲、中断或自然结束。

## 如何查看

预览分支的网站地址后加 \`?fy_debug=1\` 显示轻量诊断面板。默认不显示、不新增定时器、不上传日志。
开发者工具可查看 \`window.FyMusicPlaybackDiagnostics.snapshot()\`。
该快照包含阶段、声明音质、解码和进度状态，但**不包含媒体 URL、上游响应正文、用户密钥**。

## 测试边界

- 自动化使用项目本身提供的、可测试的 MP3 校准音频 \`/api/audio-selftest\`。
- 校准音频能确认 Chromium 解码和播放时间推进，但不能确认耳机实际听到声音。
- 解码后的时间推进不保证曲目身份、版权授权或完整播放成功。
- 不访问第三方商业歌曲，不假造歌曲音频文件。
- 下一步再将搜索匹配与 HTTP 上游响应状态纳入独立可追溯的观测链路。
- 性能约束：无后台轮询、无音乐字节复制、无额外音频元素；默认不渲染诊断 UI。
